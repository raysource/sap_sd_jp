# BRIEF — 中国語 → 日本語 翻訳（SAP SD トレーニングコースサイト `sap_jp_sd`）

あなたは SAP SD 教材の**翻訳者**です。対象は「SAP GUI（中国語インターフェース）実機スクリーンショットを使った
SAP SD トレーニングコースサイト」の中の**自然言語テキストだけ**です。HTML タグ・コード・T-code・ファイル名は
触れません（すべて ⟦n⟧ マーカーに退避されています）。

## 1. 入力と出力

- 入力: `work/ja/batch/<kind>_NN.json` — `{"kind": "...", "batch": N, "items": [{"id": "…", "zh": "…"}, …]}`
  - `zh` は翻訳対象の 1 行。`⟦0⟧` `⟦1⟧` … は**タグ / 実体参照 / エスケープ / `%s` 書式 / `{placeholder}`** に
    戻るトークン。
- 出力: `work/ja/out/<kind>_NN.json` — **純粋な JSON**（`{"<id>": "<日本語>", …}`）。
  コードフェンス・コメント・説明文は一切入れない。入力の id を**全部**含める。

```json
{"a1b2c3d4e5": "受注伝票を登録する前に得意先マスタを確認します。", "f6e5d4c3b2": "⟦0⟧販売組織⟦1⟧の定義"}
```

## 2. マーカーの規則（最重要）

- `⟦n⟧` を**すべて 1 回ずつ**使う。マーカーの個数・番号は入力と完全に一致させる。
- 日本語の語順に合わせてマーカーの**位置は動かしてよい**（タグの前後関係は自然に）。
- マーカーの中身（タグ名・属性・T-code・`%s`・`\n`）は絶対に書き換えない。マーカーを消さない・増やさない。
- 改行を入れない（1 行入力 → 1 行出力）。行頭のインデント（スペース）が入力にあればそのまま残す。

## 3. 訳し方の原則

- **読者向けの説明文**（ページ本文・ボックス・表の見出し）: 自然な**です・ます調**。
- **画面キャプション / 手順の 1 行 / 図のラベル**: 体言止め・簡潔に。**手順を勝手に足さない**（教材は「説明＋画面」型で
  簡潔なので、訳は簡潔に保つ。原文が「双击『定义销售组织』」なら「『販売組織の定義』をダブルクリック」）。
- **用語は `work/ja/glossary.json` に従う**（`terms` / `path_nodes` / `notes` / `keep_as_is`）。
  必ず最初に読むこと。用語ベースに載っていない SAP 用語は SAP 日本語版の標準訳を使う
  （例: 流通チャネル / 計算スキーマ / 出庫過転記 / 正味価額 / 明細カテゴリ / 照会・変更・登録）。
- **固有名詞は原文のまま**（颐宁 / 远东造船厂 / 铸钢泵 / Z999 など）。教材の得意先名・品目名・画面に出る値は
  **中国語のまま**残す（画面が中国語だから）。
- T-code（VA01 / VK11 / VL01N / VF01 …）、テーブル名、ファイル名（`01_1_image1078.png`）、
  `assets/...` のパス、CSS クラス、`data-*` 属性、数値・日付・金額は**そのまま**。
- 出力は**必ず日本語**。中国語（簡体字）を残さない。ただし固有名詞と、画面に出る中国語ラベル
  （例: 原文が「点击『新条目』」→「『新条目』をクリック」のように、**画面上のボタン名は中国語のまま**引用する）は例外。
- サイト自身の名前を「中国語版」と訳さない。サイトは日本語版であり、**「中国語インターフェースの実機スクリーンショット」**
  を使っている、という関係を保つ。
- 図形ラベル（`make_diagrams.py` の文字列）は、**長さを大きく増やさない**（SVG の枠に収める必要がある）。
  長い説明は短く言い換える。
