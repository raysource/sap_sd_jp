2. 板書の流れ（この順序でホワイトボードに書く）

  1. まず大きな枠「SD」を描き、周囲に隣接モジュール FI / MM / PP / CO を書き、それぞれの役割を一言で書きます（← 統合構造図を使用）。
  2. 中央に 3 つの四角形（販売組織／流通チャネル／製品部門）を描き、線で結んで「販売エリア」と書きます（← 組織図）。
  3. 下にシッピングを描きます：プラント → 出荷ポイント → 積込ポイント → ピッキング保管場所。
  4. 右側に「マスタ」の 3 ブロック（得意先／品目／条件レコード）を書き、それぞれに「何を決定するか」を一言添えます。
  5. 中央に価格設定の 4 層を書きます：条件テーブル → アクセス順序 → 条件タイプ → 計算スキーマ。さらに「計算スキーマ決定の 3 キー」を 1 本足します。
  6. 最後に横方向のタイムラインを1本引きます：引合 → 見積 → 受注 → 納入 → 出庫過転記 → 請求 → リリース → 入金（← エンドツーエンドのフロー図）。
  7. 1 つのまとまりを講じ終えるたびに、このホワイトボード図に戻って「今どの部分を説明しているか」を示します。PPT を 1 ページずつ読み上げないでください。

3. 必ず聞かれる質問と標準解答（採点ポイント）

#問題参考解答採点ポイント
1なぜ受注伝票の保存は出庫と同じではないのか？受注伝票は約束にすぎません。出庫（在庫の減少）は納入の出庫過転記、移動タイプ 601 で発生し、この時点で初めて品目伝票が生成されます。「出庫過転記 + 601 + 品目伝票」を答えられれば満点。
2どのステップで会計伝票が生成されますか？借方・貸方は何ですか？請求書のリリース（VF02）時に生成：借方 得意先売掛金（税込）、貸方 販売収益（正味価額）＋売上税。借方・貸方の向きが 1 つ違うと半分減点。
3価格はどうやって受注伝票に入るのか？計算スキーマ（販売エリア＋得意先計算スキーマ＋伝票計算スキーマで決定。教材では RVAA01）は条件タイプをステップごとに並べ、各条件タイプはアクセス順序に従って条件レコードで値を探します（PR00 単価、MWST 税など）。「計算スキーマ + アクセス順序 + 条件レコード」の3階層を答えられることが必須です。
4販売収益勘定はどう決定しますか？勘定キー（計算スキーマ内の勘定キー、例：ERL）+ 品目の勘定割当グループ + 得意先の勘定割当グループ → テーブルを参照して勘定を取得（VKOA/勘定設定）。教材では品目ごとに自製品 M1 と取引商品 M2 の 2 つの勘定に分けているだけです。3 つのキーのうち 2 つ答えられれば半分の得点。
5得意先マスタに販売エリア階層があるのはなぜ？同一の得意先でも、会社コード／販売エリアが異なれば販売データ（計算スキーマ、輸送条件、税分類、パートナ役割）を別々に持てます。そのため、全社共通の一般データのほかに販売エリアレベルのデータも必要です。「販売エリアによって異なる場合がある」と言及すれば十分です。
64 つのパートナ役割とは何ですか？受注先（発注）、出荷先（納入先）、請求先（請求対象）、支払先（支払と売掛金）。4 つの役割がすべて正しくないといけません。
7受注伝票の保存時に在庫不足のメッセージが出た。続行できる？そのまま保存を続行できます（所要量確認は保存を阻止せず、確定日を示すだけ）。後続で出荷するには在庫を補充する必要があり、教材では MB1C + 移動タイプ 501（伝票参照なし入庫）で期首在庫を入力します。「保存できる」+「501 で在庫を補充」を答えられれば可。
8なぜ請求の前に必ず納入が必要なのか？納入関連請求は納入の出荷済み数量と金額を基にします。納入がない（または出庫過転記が未実施の）場合は請求可能なデータがなく、VF01 の請求可能一覧は空になります。「請求書は納入を参照している」と答えられれば可。
9販売エリアは何で構成されますか？販売組織 + 流通チャネル + 製品部門。教材シナリオでは 1×2×2 = 4 個です。3 つのキーはすべて正しい。
10得意先に「私の荷物はどこですか」と言われたら、何を調べますか？伝票フロー（VA03/VL03N の環境 → 伝票フローの照会）で下流伝票を確認します。納入ステータス（未納入／一部／完了）と出庫ステータス（PGI 済みかどうか）を確認し、VL06O で未出荷を確認します。伝票フローまたはステータス項目のいずれかを答えられれば可。
11販売分析レポートにデータがないとき、まず何を確認しますか？① ヘッダ/明細の更新グループが有効か（タスク 31/32）；② 得意先マスタと品目マスタの統計グループが登録されているか；③ データが設定の後に生成されているか。前の 2 つを答えられれば満点。
12マスタを変更したのに、既存の伝票が変わらないのはなぜ？伝票を保存した時点のデータはスナップショットです。マスタの変更は新規伝票にのみ影響し（または伝票の手修正／再価格設定が必要）、これにより過去の伝票の追跡可能性が保たれます。「スナップショット」の意味を答えられれば可。

5. 授業でよく出る質問（その場で回答）

受講者からの質問どう答えるか
「受注タイプ OR は変更できる？」OR は標準の受注伝票タイプです。コピーして Z タイプを作ってから変更することを勧め、標準オブジェクトを直接変更しないでください。変更するのは IMG の販売伝票タイプです。
「なぜ自分の価格が 0 になる？」まず条件レコード（VK13）に該当の販売エリア + 品目の PR00 があるか照会し、次に計算スキーマ決定の 3 キーを確認します。
「得意先番号が 2 つあるのはなぜ？」受注先と出荷先は別の得意先番号にでき、パートナ役割で関連付けます。同一得意先の別番号を使うこともできます。
「見積は必ず登録しなければならない？」必須ではありません。VA01 で直接受注伝票を登録できます。見積は価格交渉がある場合に使い、追跡とフォローがしやすいのが利点です。
「納入を飛ばして直接請求できる？」標準プロセスでは不可。受注関連請求などのバリアントもありますが、コースのシナリオは納入関連請求です。
「出庫過転記を誤ったらどう直す？」順序どおりに取消：請求書（VF11）→ 出庫過転記（VL09）→ その後やり直し。伝票を直接削除しないでください。

  2. 評価：30 問のセルフチェックテスト。
