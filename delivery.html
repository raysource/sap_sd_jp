1. 納入が解決すること

問題納入はどう答えるか
何をいくつ出荷するか明細行と数量（受注数量より少なくてもよい＝部分納入）
どこから出荷するか出荷ポイント（プラント + 輸送条件で決定）+ ピッキング保管場所
いつ出荷するか納入日 / 計画納入日
倉庫が何をするかピッキング（Picking）：実際に商品を取り出し、数量を確認
いつが実際の出庫か出庫過転記（PGI）：移動タイプ 601、品目伝票を生成
一言で順序を覚える納入伝票は「出荷の計画」にすぎず、出庫過転記で初めて「実際の出荷」になります。在庫と財務の面では、納入伝票を作成した時点では何も変わりません。出庫過転記を実行して初めて在庫が減り、原価が発生します。

3. ピッキング（Picking）

ピッキング＝倉庫が納入伝票に従って品物を取り、実際に取った数量を書き戻すことです（ピッキング数量）。このステップは倉庫担当者が次のものを使って行えます：VL02N で行い、ピッキングリスト/モバイル端末も使えます。ピッキング後は納入伝票の「ピッキングステータス」が更新されます。

ピッキング関連項目意味
ピッキング数量 Picked Quantity実際にいくつピッキングしたか（納入数量と異なってもよい）
保管場所 Storage Locationどの保管場所から取るか（カスタマイジングの「ピッキング場所の割当」で決定）
バッチ / シリアル番号品目がロット管理またはシリアル番号管理の場合、ピッキング時に指定が必要
ピッキングステータス未ピッキング / 部分ピッキング / 完全ピッキング

4. 出庫過転記（Post Goods Issue, PGI）

このステップがプロセス全体の分かれ目です

「出庫過転記」を押すと：

  1. システムは移動タイプ 601で品目伝票を生成します；
  2. 在庫数量と金額が同時に減少（出庫）；
  3. 納入伝票の出荷ステータスが「完了」になります。
  4. この時点で初めてこの納入が「請求可能」になります。請求書はこのステップを待ちます。

取消にはVL09（出庫過転記の取消）を使います。伝票を削除するだけでは済みません。

在庫数量変わらない減少（移動タイプ 601 出庫）MMBE / MB52 / MB51

会計への影響なし原価出庫（CO 側の売上原価関連）品目伝票の会計伝票ビュー / CO レポート

現場で必ず暗記すること「在庫はいつ減る？」= 出庫過転記（601）。「請求書はいつ作れる？」= 出庫過転記の後。「出庫過転記を誤ったら？」= VL09 で取消（後続伝票も順に処理します）。

6. 実機画面のまとめ

今回の実習で起こりうるつまずき教材タスク 48 には実際に起きたエラーがいくつか記録されており、当サイトでは 分析ページ の第 4 節にまとめています：「現在の業務トランザクショングループではない」「作業タイプを設定できない」「CLIENT COPY が不完全」など——これらはすべて環境／設定が十分に整っていないことが原因で、操作ミスではありません。遭遇したときはまずエラー内の T-code とメッセージ番号を確認してください。
